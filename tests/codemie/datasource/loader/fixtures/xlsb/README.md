# Real XLSB test fixtures (EPMCDME-11738 follow-up item 7)

The XLSB (Excel Binary Workbook) format **cannot be written by any Python library or by
LibreOffice** — the fixtures below must be authored **by a human in Microsoft Excel** and
committed to this directory. Until they are present, `test_xlsb_real_fixtures.py` skips.

**Status: all three fixtures are committed** (`sample.xlsb`, `sample_macro.xlsb`,
`sample_protected.xlsb`), authored in Excel for Mac 16.x on 2026-07-24. All tests in
`test_xlsb_real_fixtures.py` are active. **Do not regenerate these files with a script** —
that would defeat their purpose as genuine Excel output.

These fixtures exercise the *real* python-calamine parsing path (no mocking of pandas or
calamine), covering formulas, sheet visibility, and mixed cell types that the mocked unit
tests cannot reach.

## Required file: `sample.xlsb`

Author one workbook with **exactly** these sheets (names are asserted verbatim):

| Sheet name    | Visibility   | Contents                                                              |
|---------------|--------------|----------------------------------------------------------------------|
| `Data`        | visible      | Header row + several data rows mixing numbers, dates, strings, blanks |
| `Summary`     | visible      | Header row + a **formula** row whose cached result equals `42` (see below) |
| `HiddenSheet` | hidden       | Any content                                                          |
| `VeryHidden`  | very hidden  | Any content                                                          |

### Every sheet needs a header row

The loader reads sheets with pandas `header=0`, so **row 1 is consumed as column headers**.
A sheet whose only row is data (e.g. just `Total | 42`) becomes a 0-row DataFrame whose
columns are then dropped entirely by empty-frame cleaning — it renders as an **empty
table** and content assertions fail. Always put a header row above the data, e.g.:

| Metric | Value            |
|--------|------------------|
| Total  | `=SUM(Data!B2:B5)` → 42 |

### Formula cached-value requirement (AC4)

The implementation reads **cached** formula results and does not recalculate. Put a formula
in `Summary` (e.g. `=SUM(Data!B2:B5)` or `=40+2`) arranged so its **saved cached value is
`42`** — make sure Excel calculation is set to Automatic (or force recalc) before saving,
or the workbook is saved with a stale cache. The test asserts the string `42` appears in
the `Summary` output.

If you change the cached value, update `EXPECTED_FORMULA_CACHED_VALUE` in
`test_xlsb_real_fixtures.py` to match.

## Variants (committed)

- `sample_macro.xlsb` — macro-enabled variant with the **same sheet layout and cell data**
  as `sample.xlsb` (all 4 sheets, cached `42` in `Summary`), plus a hand-recorded VBA
  macro (`xl/vbaProject.bin` is present in the container). Confirms macro workbooks parse
  identically with the VBA part ignored — spreadsheet readers never execute macros.
  VBA **cannot be injected programmatically** (Excel blocks VBA-project access by
  default), so this file was recorded manually in Excel and cannot be regenerated by
  script. Excel shows an Enable Macros prompt on open; enable it if re-saving.
- `sample_protected.xlsb` — password-protected workbook (password: `codemie123`).
  calamine raises `PasswordError`; the loader surfaces `UnreadableWorkbookError`.

The **corrupt** fixture is generated inside the test by truncating `sample.xlsb`; do not
commit a separate corrupt file.
