- **AC7 (secrets/sanitizer) — unsanitized attacker-controlled `state` reaches two log lines.** `_common.py:146-148` returns `state[:12]` verbatim with no CWE-117 sanitization, and `_oauth2_callback.py:482` (entry INFO) and `:525` (IdP-error WARNING) pass it the raw `state` query parameter of the *unauthenticated* callback route, which `router.py:369` declares as `str | None = Query(default=None)` with no pattern or length bound. Verified in-repo: `_log_state_prefix("a\nWARNING: x forged")` returns `'a\nWARNING: x'`, and `codemie/configs/logger.py`'s `LogFormatter` performs no newline escaping (its `format` even converts `\\n` back to a real newline). A request to `/v1/mcp-auth/oauth2/callback?state=%0aWARNING:%20…` therefore forges log lines — the exact CWE-117 hazard `_sanitize_log_value` exists to close, on the one field this ticket adds to an anonymous endpoint. AC7 requires *every* logged string to pass through the sanitizer. Fix: sanitize inside `_log_state_prefix` (truncate then `_sanitize_log_value`, or restrict to an allowlisted charset) and add a callback-side test asserting no CR/LF survives from a hostile `state`.

- **AC8 (observation must not break the flow) — the initiate paths parse the authorize URL outside the guarded helper.** `_initiate.py:114`, `:232`, `:318` and `:416` each run `dict(parse_qsl(urlsplit(response.auth_url).query)).get("state")` with no try/except, immediately *before* calling the deliberately non-raising `_describe_authorize_request`. Verified in-repo: `urlsplit("https://[::1/oauth2/authorize?state=abc")` raises `ValueError: Invalid IPv6 URL`. Because these lines run after `_build_enterprise_initiate_response` has already minted the state and written the PKCE entry, a malformed authorize endpoint converts a successfully-built flow into a 500 — the flow is broken *by* its own observation, which is precisely what AC8 forbids. The AC8 tests only exercise `_describe_authorize_request` directly, so this path is uncovered. Fix: have `_describe_authorize_request` also return the `state`/`RelayState` value (one guarded parse instead of two, removing the 4× duplication), and add a test that drives a malformed `auth_url` through an initiate path asserting the response still returns.

- **AC1 (joinable initiate line) — the discovered path logs the auth-config id under a different key than the rest of the flow.** `_initiate.py:236` emits `discovered_auth_id={snapshot.discovered_auth_id}`, while `_discovery.py:215` and `_oauth2_callback.py:522` emit the identical value as `auth_config_id=` (`codemie_enterprise/mcp_auth/discovered_flow.py:350` sets `auth_config_id=discovered_auth_id`). AC1 names `auth_config_id` for every initiate path, and the whole point of the ticket is joining lines across the flow; a `auth_config_id=<id>` log query silently misses every discovered initiate. Separately, the recovery line (`_initiate.py:320-325`) omits `auth_config_id` altogether. Fix: log `auth_config_id=` on the discovered line (keep `discovered_auth_id` as an alias only if something depends on it) and add the recovery flow's auth-config id if the enterprise response exposes it, otherwise record in the spec why it cannot be sourced.

- **AC6 / cross-repo contract — `waited_ms` has a 1-hour ceiling the frontend can exceed, and the failure is silent by design.** `_diagnostics.py:47` declares `waited_ms: int | None = Field(default=None, ge=0, le=3_600_000)` and `test_callback_diagnostics_rejects_waited_ms_over_ceiling` pins the 422. The UI value is `resolvedTimeoutMs` (`useAuthCallbackListener.ts:166`), derived from the admin-settable `MCP_AUTH_TIMEOUT_SECONDS` runtime config (`appInfo.ts:145`) through `getPositiveInteger`, which imposes no upper bound. An operator raising the timeout above 3600s makes every timeout beacon 422 — and since the beacon swallows all transport outcomes, the server-side record AC6 mandates disappears without a trace, in exactly the long-wait scenario most worth recording. Fix: either clamp `waited_ms` client-side to the model's ceiling, or raise/remove the ceiling and rely on the existing `int` bound.

- **Spec scope list — `router.py` is modified but unlisted.** The diff changes `src/codemie/enterprise/mcp_auth/router.py` at `:327` and `:428` to pass `mcp_config_id` into `build_oauth2_initiate_response` / `build_saml_initiate_response`. This is required to satisfy AC1 and is correct, but neither the spec's "In scope — `codemie`" list nor the ticket's "Files expected to change" table names it, so a scope-conformance check on the file list reports a stray file. Fix: add `router.py` to the spec's in-scope list.

- **Spec Testing section — the two tests standing in for AC7 and AC8 do not cover the code paths where those ACs actually fail.** `test_describe_authorize_request_never_raises_on_value_error` covers the helper but not the unguarded parse at the four initiate call sites; the `state not in message` assertions inspect only messages captured from `_initiate.logger`, so the callback-side `_log_state_prefix` usage — the one place the value is attacker-controlled — has no secrets or injection assertion at all. Both suites pass today (94 backend / 16 UI), which is the problem: green tests are being read as AC7/AC8 evidence they do not provide. Fix: add (a) an initiate-path test with a malformed `auth_url`, and (b) a callback test posting a `state` containing `\n` and asserting the emitted log line contains no CR/LF.

- **Cross-repo semantics — `opener_present: false` is hardcoded in the timeout beacon.** `useAuthCallbackListener.ts:114` always sends `opener_present: false`, but the field's meaning on `OAuth2CallbackDiagnostics` is "the bridge page could still see its `window.opener`" — a property of the popup, not of the parent hook that fires this beacon. The value is logged verbatim at `_diagnostics.py:66`, so timeout rows are indistinguishable from genuine lost-opener rows on that field. The distinct message prefix keeps the two classes separable, so this is a data-quality rather than a correctness break. Fix: make `opener_present` optional on the model and omit it from the timeout payload, or add a `phase`-aware note so dashboards do not read it as an opener loss.
