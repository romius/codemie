- Spec 2026-08-05 section 4 defines the SSE interrupt signal as `StreamedGenerationResult.tool_call_pending`, but that field (`src/codemie/chains/base.py:138`) is never populated anywhere in `src/codemie`; the actual runtime signal is a `Thought(interrupted=True)` object emitted from `ask_for_tool_confirmation` in `src/codemie/agents/tool_confirmation/tool_call_confirmation_mixin.py`. Any consumer built against the documented contract will not see the field it was told to expect.
- Spec 2026-08-10's priority rule ("assistant-level flag is a hard ceiling - the request flag cannot disable it") is contradicted by `src/codemie/service/tool_permissions_service.py`: when `allow_override` is `True` (the default for a new `ToolPermissionsConfig`), a per-request `tool_call_policy` override fully replaces a stricter assistant-configured policy instead of only raising it. This is confirmed by the project's own test `tests/codemie/service/test_tool_permissions_service.py::test_request_override_beats_assistant`, which asserts an `ASK_FOR_APPROVAL` assistant is downgraded to `AUTO_APPROVE` by request override — a caller can bypass an assistant's mandatory tool-call confirmation.
- Spec 2026-08-10 explicitly lists "No changes to `POST v1/conversations` or the conversation entity" as Out of Scope, but `src/codemie/rest_api/models/conversation.py` adds a persisted `tool_call_policy` column to `Conversation` (plus migration `src/external/alembic/versions/v4w5x6y7z8a9_add_tool_call_policy_to_conversations.py`) and `UpdateConversationRequest` gains a `tool_call_policy` field in `src/codemie/core/models.py`.
- Design 2026-08-05 section 2.1 specifies `ToolPermissionsConfig.require_confirmation: bool = False`; the implemented model (`src/codemie/rest_api/models/assistant.py`) instead has `tool_call_policy: ToolCallPolicy` and `allow_override: bool`, with no `require_confirmation` field anywhere in the codebase.
- `reject_tool_call` in `src/codemie/agents/tool_confirmation/tool_call_confirmation_mixin.py` denies every tool call in `pending.all_tool_call_ids`, but only the first tool call of a multi-call AI turn is ever surfaced to the user as the pending confirmation (`ask_for_tool_confirmation` only builds a `ToolCallPendingEvent` from `tool_calls[0]`). A user pressing Deny on the one dialog they saw silently also cancels any sibling tool calls in that turn that were never shown to them.
- `ToolCallResumeRequest` (`src/codemie/rest_api/routers/assistant.py`) omits the `pending_tool_call_id` field that design 2026-08-05 section 5.2 specifies the client must echo back; the server instead trusts only its own stored pending state, so the resume call cannot be validated against the specific tool call the client believes it is resolving.
- `ToolPermissionsService.get_effective_permissions` (`src/codemie/service/tool_permissions_service.py`) drops the `user: Optional[User]` parameter that design 2026-08-05 section 3.3 specifies as the hook for future per-user overrides.
